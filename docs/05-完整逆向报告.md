## 3. ★ 反推符号表（本次逆向最关键的方法）

`kernel.dll` 里每个日志点都会构造一个**栈上 frame**：

```asm
mov  dword ptr [eax], 9                  ; frame.type = 9 (日志)
mov  dword ptr [eax+0x1c], 0x11259ef8    ; frame.func = "calculate_target_speed"
mov  dword ptr [eax+0x20], 0x7e          ; frame.line = 126
mov  dword ptr [eax+0x18], 0x112xxxxx    ; frame.file = 源文件（部分帧有）
call 0x103c9110                          ; __CxxThrowException → 由 EH 统一 swallow
```

于是**只要把 `[reg+0x1c] ← 字符串指针` 和紧随的 `[reg+0x20] ← 小整数` 配对**，就能批量还原
`(函数名, 源码行号)`。实现见 `re/tools/logsites.py`（扫描 + 按函数起点归并）、
`re/tools/funcmap.py`（输出 CSV）。

**成果**：
- 触发 1531 处日志点 → 归并出 **1531 个函数条目 / 719 个唯一函数名**（同名不同文件会重名，属正常）
- 产物：`re/out/funcmap_kernel.dll.csv`（`func_rva, func_va, names, src_lines`）
- 副产品：**行号集群**能反推源文件切分（见 04 篇 §7）

**局限**（必须写明）：
1. 只有"打了日志"的函数才有名字；`kernel.dll` 里大量内联/无日志函数仍然是 `sub_XXXX`。
2. 行号是**该 .cpp 内的行号**，不是全局行号；同名函数（如 26 个 `start`）需要靠行号区间 + 调用关系区分。
3. 是否与官方 PDB 一致无法验证（PDB 未随包发布）——但函数名与行号来自编译器写入的字符串常量，
   **可信度等同于源码里的 `__FUNCTION__`/`__LINE__`**。

### 4.2 `SpeedLimitor`（限速器）× 2 + `NetworkStrategy`

**（a）`qingluan::download::SpeedLimitor` —— 由 thunk `0x2dd780` 反推的布局（最可靠）**

```c
struct SpeedLimitor {
    /*+0x00*/ void** vtbl;
    /*+0x08*/ AccumulateTokenBucket bucket;   // 成员对象，sizeof ≈ 0x2c
    /*+0x38*/ int32  restrict_ratio;          // 0..100
    /*+0x3c*/ bool   enabled;
    /*+0x40*/ uint64 max_speed;               // B/s
};
```
依据：`0x2dd780` 里 `lea esi,[ecx]` → `call calc` → `add esi,8` → `call bucket.set_rate`，
且 `set_restrict_ratio`(0x2dcde0) 读 `[ecx+0x38]`、`calc`(0x2ddb90) 读 `[ecx+0x40..0x47]`、
`enabled` 判在 `[ecx+0x3c]`。**三处偏移互不冲突，可认为成立。** ✅

**（b）`qingluan::upload::SpeedLimitor`** —— 同名 RTTI 类，上传侧独立一套，
对应 `set_upload_speed_limit`(0xe2c55) 与 `calculate_all_upload_task_connection`(0x2fdb40)。

**（c）网络策略对象**（`0x2e43a0` 的 this，0x1d98 字节构造）—— 与限速器是**不同实例**：

```c
struct NetworkStrategy {              // 由 0x2e43a0 与 0xb8430/0xb8480/0xb8440 交叉反推
    /*+0x108*/ Timer  t_short;        // 建出后 set 0x1388 ms、-1
    /*+0x110*/ Timer  t_long;         // 0x5265c00 ms (24h)、-1
    /*+0x180*/ Obj    speed_ctl_cfg;
    /*+0x354*/ bool   enable_network_detect;
    /*+0x360*/ int32  detect_low_speed_thrshold;
    /*+0x364*/ int32  detect_medium_speed_threshold;
    /*+0x368*/ int32  below_threashold_probability;
    /*+0x36c*/ Prob   below_prob_obj;
    /*+0xd3c*/ int32  above_threashold_probability;
    /*+0xd40*/ Prob   above_prob_obj;
    /*+0x1710*/ bool  enable_cdn_detect;
    /*+0x1711*/ bool  cdn_detect_hit;
    /*+0x1730*/ Prob   cdn_detect_probability;   // 默认 10
    /*+0x1728/0x172c*/ uint64 next_detect_deadline;  // mt19937(seed=GetTickCount()) 取 60..10800
    /*+0x2104/0x2100*/ uint64 network_detect_download_flux;
    /*+0x2110*/ bool  use_increase_cdn_speed;
    /*+0x2128*/ bool  use_svip_speed_control;
    /*+0x214c*/ int32 max_pkg_download_count;    // 默认 5
    /*+0x2150*/ int32 use_package_download_ver_2;
    /*+0x2154*/ bool  enable_network_slow_check;
    /*+0x2155*/ bool  enable_firewall_check;
    /*+0x2158*/ int32 slow_speed_threshold;
    /*+0x215c*/ int32 (置 0)
    /*+0xa10*/ int32  subbit_count;
    /*+0xa14*/ int32  conn_level1;    // 缺省 4
    /*+0xa18*/ int32  conn_level2;    // 缺省 2（level3 共用此槽，见 0xb8440）
    /*+0xa1c*/ int32  conn_level3;    // 缺省 1
    /*+0xa60*/ int32  current_net_level;
};
```
这解释了 02 篇 §8 提到的那批"只出现在代码里、不在 YunLogic 模板里"的 key：
它们是**服务端 CMS 下发 + 本地 `kernel_kernelb.cfg` 覆盖**的运行时参数。

**（d）`AccumulateTokenBucket` 的 4 参构造**（`0x2e43a0` 内 `push 0x48; call operator new` 之后）：
`{container, alloc, capacity, refcount}`，随后 `call 0x102900c0` 设定容量，再 `call 0x102901e0` 装入
`this+0x180`。🟡 该处的"容器"看起来是**每任务限速器列表**，未逐一确认。

## 8. 方法论（可复用到同类目标）

1. **先看资源段**：大 DLL 的 `.rsrc` 常常是"打包器"，`kernel.dll` 22.8 MB 资源里藏着 3 个 PE。
2. **不要迷信 PDB 缺失**：MSVC 的日志/异常宏把 `__FUNCTION__`/`__LINE__` 写进了 `.text`，
   这是**免费的符号表**。本方法把 0 符号恢复到 1531 个函数名，成本 ~40 行 Python。
3. **日志是最好的规格说明**：`XOR 0x8A` 一破，服务端下发的 JSON、限速字段、行号、模块名全在里面。
4. **按"字符串 → 引用 → 函数 → 调用图"逐层收口**：`kb.py` 的 `xrefs()` 要同时试
   **绝对 VA** 与 **RVA** 两种形式，否则会漏（本次 `0x2ddb90` 的调用者就是靠 `e8 rel32` 扫描才找到）。
5. **常量是最硬的证据**：`0x1F400000`（"不限"哨兵）、`0x4000`（桶最小容量）、
   `122880`（120 KiB/s）在不同函数里反复出现，可用"整数立即数全量扫描"快速定位语义相关代码。
6. **不要硬找 vtable**：该 PE 无 `.pdata`/无重定位表辅助、RTTI 描述符引用为零，
   唯一可行的 vtable 定位法是"构造函数里 `mov [this], imm32` + imm32 落在 `.rdata` 且后面连续是 `.text` 指针"。

## 9. 动态验证（Frida）—— 具体点位

`re/frida/hooks.js` 已给出可直接运行的脚本。**运行方式见 `re/frida/README.md`**

> **跑之前先做两件不需要 Frida 的事**：

>    全部 OK 才说明你的客户端版本和这份报告一致；有 BAD 就说明需要按 §3 重新定位。

> `TypeError: ... is not a function`。本仓库 `hooks.js` 已改成
> `Process.getModuleByName(...).findExportByName(...)` + `Module.getGlobalExportByName(...)` 的兼容写法。

| `0x2dcde0` | `set_restrict_ratio` | `[ecx+0x38]` 旧值 / 新值（arg） | 谁在改下限、什么时候改 |

> 在那个函数里 `this.context.ecx` 不可靠；只读返回值。
